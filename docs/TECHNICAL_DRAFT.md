# KB Registry 기술자료 — 로컬 초안

> 대상 프로젝트: MCP:KB-Registry (MKR). MS-A-2 원문은 YouTrack HTTP 429로 확인하지 못했습니다. 아래는 템플릿 적용 전 초안이며 YouTrack 게시 완료본이 아닙니다. 문서 제목의 구분은 자료 계층이며 KB ID나 YouTrack 문서 번호가 아닙니다.

## 계층 지도

```text
KB Registry
├─ 식별
│  ├─ 불변 문서 ID
│  ├─ 가변 경로
│  └─ 카테고리 표시 번호
├─ 저장 무결성
│  ├─ SQLite 트랜잭션
│  ├─ 최초 초기화 잠금
│  ├─ UNIQUE·외래 키
│  └─ 이력·논리 삭제
├─ 파일 동기화
│  ├─ Source of Truth
│  ├─ Pending → Committed
│  └─ 검증·복구 제안
└─ 실행 경계
   ├─ MCP stdio
   ├─ 경로 제한
   └─ Writer·YouTrack 책임 분리
```

각 절은 한 개념의 정의·구현·주의점을 설명하는 독립 자료로 분리할 수 있습니다.

## 불변 문서 ID

- **정의:** 제목·경로·분류가 바뀌어도 같은 문서를 가리키는 식별자입니다.
- **구현:** Registry만 `KB-000001` 형식으로 발급합니다. 기존 파일의 ID는 충돌 검사를 거쳐 재사용하며 번호를 낮추거나 재활용하지 않습니다.
- **주의:** 경로가 같은 문서와 내용이 같은 문서를 자동으로 동일시하지 않습니다. 복사한 파일에 같은 ID가 남으면 중복 오류입니다.

## 가변 경로

- **정의:** ID와 독립적으로 갱신 가능한 문서 위치입니다.
- **구현:** KB 루트 기준 상대 경로를 저장하고 이동 시 기존 ID 및 파일을 검사합니다. 디렉터리 이름에 카테고리 구조를 강제하지 않습니다.
- **주의:** 파일 이동은 Writer가 수행합니다. Registry는 파일을 이동하거나 내용을 수정하지 않습니다.

## 카테고리 표시 번호

- **정의:** 사람이 읽는 `RL-001` 같은 분류용 번호입니다. 문서의 영구 ID가 아닙니다.
- **구현:** 안정적인 내부 category ID와 가변 코드를 분리합니다. 번호는 카테고리별 증가하며 할당 이력을 보존합니다. 같은 카테고리 반복 지정은 멱등, 해제 후 재지정은 새 번호입니다.
- **확정 정책:** 문서당 카테고리 하나 또는 `null`. 코드 변경은 같은 카테고리의 증가 번호를 이어갑니다. 과거 코드도 예약하고 카테고리를 논리 삭제합니다.

## SQLite 트랜잭션

- **정의:** 여러 DB 변경을 전부 반영하거나 전부 취소하는 원자적 작업입니다.
- **구현:** 쓰기 작업은 `BEGIN IMMEDIATE`로 직렬화하고 `busy_timeout`으로 잠금 대기를 허용합니다. WAL은 읽기와 쓰기의 간섭을 줄입니다.
- **주의:** DB 트랜잭션이 Markdown 파일 수정까지 원자적으로 묶지는 않습니다. DB는 SQLite 잠금이 정상인 로컬 파일시스템에 두어야 합니다. 여러 호스트의 네트워크 파일시스템 공유 DB 운영은 지원 범위가 아닙니다.

## 최초 초기화 잠금

- **정의:** DB가 아직 없는 여러 프로세스가 WAL 모드와 스키마를 동시에 초기화하지 못하게 하는 운영체제 잠금입니다.
- **구현:** Linux 표준 라이브러리 `fcntl.flock`으로 DB 옆 `.init.lock`을 잠근 상태에서 WAL 전환·스키마·루트 연결을 초기화합니다. 이후 일반 업무 트랜잭션은 SQLite가 담당합니다.
- **주의:** 최초 WAL 전환은 `busy_timeout`만으로 동시성을 보장하지 못하는 사례가 재현되었습니다. 잠금 파일을 지우면 대기자가 다른 inode를 잠글 수 있으므로 보존합니다. 프로세스가 종료되면 실제 잠금은 커널이 해제합니다.

## UNIQUE·외래 키

- **정의:** 중복 값과 존재하지 않는 참조를 DB 자체에서 거부하는 제약입니다.
- **구현:** 문서 ID·현재 경로·과거 표시 번호·문서/Issue 조합 등을 유일하게 관리하며 foreign key 검사를 켭니다.
- **주의:** 애플리케이션의 사전 조회만으로 동시성 중복을 막을 수 없으므로 DB 제약과 잠금을 함께 사용합니다.

## 이력·논리 삭제

- **정의:** 과거 기록을 지우지 않고 비활성 상태로 남기는 삭제입니다.
- **구현:** 카테고리 삭제 시 문서는 유지하고 현재 분류만 해제합니다. 과거 번호와 경로·분류 변경 기록을 보존합니다.
- **주의:** 운영 DB 삭제는 ID 재사용 위험을 만듭니다. DB와 문서는 함께 백업하되 별도 권한으로 관리합니다.

## Source of Truth

- **정의:** 충돌 때 어느 저장소의 값이 기준인지 정한 책임 규칙입니다.
- **구현:** ID·분류 번호·경로·Issue 매핑은 SQLite, 제목·본문·LaTeX·기타 사용자 내용은 Markdown/YAML이 기준입니다. YAML의 Registry 소유 필드는 DB 값을 투영한 사본입니다.
- **주의:** 기존 문서 최초 가져오기는 명시적인 검증 경계입니다. 등록 이후 YAML 값으로 DB를 무조건 덮어쓰지 않습니다.

## Pending → Committed

- **정의:** DB 예약과 파일 작성 사이의 부분 실패를 드러내는 등록 절차입니다.
- **구현:** 예약 결과의 `expected_frontmatter`를 Writer가 반영한 후 `confirm_document`가 실제 파일의 메타데이터 일치를 확인합니다. 파일 누락·값 불일치는 확정을 막습니다. 메타데이터 변경은 다시 Pending으로 만듭니다.
- **주의:** Pending은 실패만을 뜻하지 않습니다. 작성 중이거나 아직 확인하지 않은 상태도 포함합니다. 확인 이후의 파일 변경은 다음 검증에서 탐지합니다.

## 멱등성

- **정의:** 같은 요청을 재시도해도 불필요한 ID·번호·관계를 추가하지 않는 성질입니다.
- **구현:** 현재 경로, 등록 ID, 선택적인 idempotency key 및 DB 유일성 제약으로 중복 예약을 방지합니다. 같은 문서와 Issue를 반복 연결해도 관계는 하나입니다.
- **주의:** 이동한 문서의 재등록은 새 경로로 임의 발급하지 말고 이동 API로 처리합니다. 해제 후 재할당은 새로운 의도이므로 새 표시 번호를 씁니다.

## 검증·복구 제안

- **정의:** Registry와 문서의 차이를 읽어서 분류하고 안전한 수정 방향을 제시하는 작업입니다.
- **구현:** 누락 파일·미등록 파일·중복 ID·잘못된 YAML·메타데이터 불일치·미확정 상태 및 SQLite 무결성을 검사합니다. `reconcile_document`는 Writer가 적용할 기대 메타데이터를 반환합니다.
- **주의:** 복구 제안은 파일 수정이나 자동 성공 판정이 아닙니다. Writer 적용 후 다시 확인해야 합니다.

## MCP stdio

- **정의:** 클라이언트가 필요할 때 서버 프로세스를 실행하고 표준 입출력으로 JSON-RPC를 주고받는 전송 방식입니다.
- **구현:** FastMCP 인터페이스가 Registry 비즈니스 로직을 호출합니다. 로그는 stderr로 보내고 stdout은 프로토콜 전용입니다.
- **주의:** systemd·포트·ContextForge 등록은 필요하지 않습니다. 클라이언트가 연결한 동안 프로세스가 살아 있을 수 있습니다.

## 경로 제한

- **정의:** Registry가 승인된 문서 루트 밖을 읽지 못하도록 제한하는 경계입니다.
- **구현:** KB 루트와 입력 경로를 정규화하고 경로 이탈·외부 symlink·허용되지 않은 확장자를 거부합니다. Markdown 및 선택적 Quarto 문서를 읽습니다.
- **주의:** 로컬 stdio는 독립적인 인증 서버가 아닙니다. 신뢰하지 않는 사용자가 KB 디렉터리·부모 경로를 동시에 교체하지 못하도록 OS 권한을 유지해야 합니다.

## Writer·YouTrack 책임 분리

- **정의:** 식별자 관리, 문서 작성, 외부 이슈 변경을 각각 다른 주체가 담당하는 구조입니다.
- **구현:** Registry는 메타데이터만 관리하고 파일은 읽기 전용입니다. Writer가 frontmatter와 본문을 작성합니다. Tracker가 실제 YouTrack 변경을 수행한 뒤 확인된 Issue ID를 Registry에 연결합니다.
- **주의:** `link_youtrack` 성공은 해당 Issue의 원격 존재·권한·상태를 검증했다는 뜻이 아닙니다. 기술자료도 템플릿 확인·작성·게시 결과를 구분해야 합니다.
